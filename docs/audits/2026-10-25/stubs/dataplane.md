- **Rule fields** (`config.go:782-821`): ID/order, zones, source/destination tokens, protocol, action/log, identities, ICS and schedule are retained by `pkg/cp/compile/compile.go:73-99`. Kernel has L3/L4/action/log readers; evaluator has identity/schedule/ICS readers. Gaps are path parity (S1–S5) rather than absent compiler fields. General decoder/ICS-predicate conformance belongs to D.1/3.2 and the ICS recon lane; this sweep does not certify every protocol-specific field.
- **Interface fields** (`config.go:355-398`): netcfg consumes type/parent/VLAN/members, addresses/mode/gateway and device; ownership uses logical bindings; CP local-input generation consumes access flags (`pkg/cp/compile/compile.go:102` onward). Name/alias/zone also drive lookup/display. No new unconsumed interface setting established. Address ownership is S17. Bridge creation is real but is not evidence of transparent L2 filtering; the explicit bridge profile is already Stage 4, not a new promised production-physical-interface feature.
- **NAT fields** (`config.go:621-639`): Enabled controls postrouting masquerade; EgressZone/SourceZones are read; per-forward Enabled/IngressZone/Proto/ListenPort/DestIP/DestPort/AllowedSources render DNAT and auto-accept. Descriptions are metadata. Gaps are authorization and hardcoded secondary postrouting (S4/S12), not a wholly fake NAT subsystem. No promised SNAT pools/1:1 NAT/NAT66 found to ticket as stubs.
- **Routing fields** (`config.go:644-675`): named gateway address/interface are resolved; route destination/gateway/interface/table/metric render netlink requests; PBR priority/src/dst/table render rules. Alias/description are labels. Unsupported family acceptance is S15; deletion/ownership is S16. Dynamic routing, ECMP and health-based failover have no advertised configuration in these surfaces and are not invented requirements here.
- **Verdict fields/actions** (`pkg/dp/verdict/verdict.go:15-32`): allow/drop conversion and temporary TTL blocks are live; generic reset/rate/tag have no runtime consumers (S9–S11). - **ExportConfig** (`config.go:503-508`): enabled/format/target/filter have no live exporter construction/reader found (S19). Actual formatter and file/network sink implementations are not stubs in isolation.

## Validation ownership and evidence needed

No source changes, commits, runtime tests, traffic injection, Docker starts or network modifications. A source-backed defect is **not** experimental proof of packet-path impact. Implementation owners should own these narrow regressions, with orchestrator-owned isolated Linux integration/full runs:

- **CP/identity + enforcement:** S1/S2/S4/S5/S6/S15/S22 need a shared preview/evaluator/nft corpus and disposable-netns positive/negative packets. S4 includes translated-destination collisions; S6 includes foreign nft sentinel, reload TTL continuity and TCP/UDP/source-port collateral checks. Identity lifecycle requires the external authority/broker owner.
- **Capture/protocol + engine:** S3 needs first-command server-state assertions with queue unset, decoder disabled, exclusions, and inline capture failures. Existing opt-in NFQUEUE and IEC kernel fixtures are useful foundations (`pkg/dp/capture/nfqueue_kernel_linux_test.go`, `pkg/dp/enforce/iec104_kernel_linux_test.go`). Do not reinterpret intentional generic malformed/panic PASS behavior as an accidentally empty stub: `pkg/dp/engine/us_packet.go:27-35,82-88,165-184` explicitly defines it. Any stronger preventive/failure profile is a product/contract change.
- **Session/conntrack + SRA:** S9/S13/S14 require Linux kernel inventory/CT delete plus an endpoint-liveness/reconnect assertion, not just JSON success or raw-socket send success. `pkg/dp/session/injector.go:24-26` correctly limits SendRST success to socket acceptance.
- **Netcfg/ownership:** S12/S16/S17 need fresh namespaces with custom zones, valid priority outside the managed range, all-intent deletion, and foreign route/rule/address sentinels. Do not run namespace-wide nft flush in a shared project lab.
- **eBPF/performance:** S7 requires real Linux bytecode/attach/drop/expiry/counter evidence; it is not validated by fallback tests. S10 needs per-flow throughput/burst measurement; S11 needs tuple-reuse/tag lifetime tests.
- **Telemetry/learner/export + CP/app:** S18–S21 need inherited-mode profiling, collector-delivery/loss, split/coalesced event-vs-packet accounting, and same-boot transient-apply/capture-readiness tests. S20 already has another worker; hand off evidence rather than duplicating edits.
- **NOT RUN:** Go package/unit/race suites, Linux build/vet/lint, privileged kernel/netns tests, Compose smoke, benchmarks/soak, and live API/CLI/UI. Recon is source-only. Future engine/capture lifecycle edits require the entire touched package under race, not only a new regression.
