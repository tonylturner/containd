## Affected interfaces and validation ownership

- **Identity/SSH owner:** S1, S2, S4, S7, S8: real SSH password/key authentication, wizard prompts, host-key deadlines, store/API failure injection. S1 must cover native OS-shell entry, not just API token rejection.
- **Mgmt/runtime and config owners:** S3, S5, S6, S9–S11, S20: candidate→commit→observed runtime, every warning header, external trust test server, HTTPS-only startup and CLI/health. Coordinate staged-config lane; do not mistake its future changes for current evidence.
- **Release/supply-chain owner:** S12–S15: isolated workflow/promotion failure tests and remote per-platform image/SBOM/signature inspection. Another lane already owns the release workflow; this report does not supersede it.
- **Quality/CI and Linux harness owners:** S16, S18, S19, S21, S23: headless required-route gate, permissive-firewall/missing-tool/missing-counter mutations, docs-provenance fixture, process/SSH exit-status assertions. Orchestrator owns integrated full suites and isolated Docker runs.
- **Dataplane/export owners:** S17, S22: real Linux packet path and production SIEM collection; shared interfaces are immutable rule snapshots and canonical emitted events. Duplicate ownership with adjacent sweep areas is intentional because README explicitly advertises these capabilities.

- Interface management-access gates reload store state in their callbacks; non-Linux CLI diagnostics return platform errors by design. Neither is a stub finding here.
