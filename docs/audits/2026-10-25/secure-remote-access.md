## 3. Bugs and debt — ranked

Severity is relative to a non-lab SRA exercise where an attacker can reach the advertised ingress; deliberately insecure lab mode is not itself an authentication vulnerability. These are static findings, not exploited CVEs.

### High — repair before an “SRA-ready” claim

**H1. SSH bypasses web account assurance and is a native-shell ingress. Verified:** password/key callbacks check admin plus password/key, not `MustChangePassword`, MFA enrollment/requirement or TOTP (`pkg/mp/sshserver/server_auth.go:58-111`). Password is automatically enabled when the key directory is absent/empty, even if config `allowPassword` is false (`pkg/app/mgmt/ssh_support.go:124-145`); explicit environment override can disable it. Native bash is reachable from CLI `shell`/`bash` (`server.go:329-335`) as well as Linux shell mode (`:251-259`). **Inferred:** the universal first-boot password can reach an admin shell without the web forced-change gate; required/enrolled MFA does not protect SSH. Fix assurance parity or reject unsupported MFA accounts; make bootstrap explicit, not an implicit override. Native shell must remain appliance-admin-only, never a vendor grant.

**H2. SSH brute-force buckets vary with source port. Verified:** `RemoteAddr().String()+username` (`server_auth.go:63-90`) includes TCP source port. **Inferred:** reconnecting gets a new bucket; per-connection SSH retry limits cannot replace a host/account limiter. Normalize source IP and test reconnects, IPv6 and shared-NAT behavior.

**H3. Password reset/MFA changes do not revoke or step up existing sessions. Verified:** password/TOTP/requirement methods only update user rows (`pkg/cp/users/store.go:420-488`); session rows/claims contain no MFA method or auth epoch (`:142-149,504-511`; `api/http/auth.go:359-370`). Deletion **does** remove sessions (`store.go:396-416`), so do not describe all invalidation as absent. **Inferred:** an already issued password-only token survives a password reset and can retain full API rights after MFA enrollment. Revoke affected sessions transactionally or introduce session assurance/security-version checks. Active native SSH shells need separate termination, not just JWT invalidation.

**H4. “TLS enabled” can publish plaintext; backend hop is always HTTP. Verified:** reverse template explicitly falls back to plain `listen` without `certRef` (`pkg/cp/services/proxy.go:757-777`); validation never requires a cert (`pkg/cp/config/validate_services.go:123-148`); backend uses `proxy_pass http://`. **Inferred:** operator intent is contradicted, risking credentials/content exposure. Reject incomplete TLS config, validate certificate presence/match and design authenticated TLS upstreams where needed. This is independent of deliberate plaintext lab targets.

**H5. OpenVPN client credentials are durable unmanaged identities. Verified:** client key/cert reused by sanitized name, three-year validity (`openvpn_pki.go:131-185`); managed server has no `crl-verify`, local user plugin/MFA hook or per-client ACL (`vpn.go:584-616`); HTTP routes only list/create/download (`api/http/server.go:255-257`). **Inferred:** removing a local vendor user cannot revoke an exported VPN identity. Implement issuance inventory, stable subject binding, CRL/revoke plus active-client disconnect; expiration alone is not offboarding. Short-lived certs complement, not replace, termination.

**H6. OpenVPN changes can remain unapplied indefinitely. Verified:** renderer overwrites a stable config filename (`vpn.go:373-377`), but running process is left untouched whenever that filename is unchanged (`:224-235`). **Inferred:** pool, route or client-isolation changes saved through the API need not affect the daemon. Compare rendered revision/material hash; safely restart when content changes and expose applied revision. Also no automatic restart/backoff is visible after `waitOpenVPN` records process exit (`:263-299`): supervised start/stop is not self-healing availability.

**H7. WireGuard assigns the network address instead of requested host address. Verified:** `ParseCIDR`'s first result is discarded and `ipnet` goes directly to `addAddr` (`pkg/dp/netcfg/wireguard_linux.go:132-138`), which uses `ipnet.IP` for `IFA_LOCAL`/`IFA_ADDRESS` (`netlink_addr_linux.go:22-32,72-73`). **Inferred:** documented `10.8.0.1/24` becomes `10.8.0.0/24`, breaking expected peer gateway addressing. Preserve host IP and test exact netlink attributes on Linux; runtime handshake not run here.

**H8. CLI convenience writes destroy existing restrictions/config. Verified:** `set proxy forward` posts a new partial object; server replaces full forward config (`pkg/cli/cli.go:355-374`; `api/http/service_handlers.go:441-448`). `set proxy reverse on/off` posts only enabled and loses all sites (`cli.go:377-385`; handlers `:477-484`). Port-forward add ignores the existing NAT GET error then posts a new NAT object (`pkg/cli/port_forward.go:216-225`). **Inferred:** a toggle can clear domain/log settings (empty domain list renders `*`, `proxy.go:190-193`) or remove publication/SNAT/other forwards. Require successful read/merge or dedicated patch semantics plus revision conflict detection.

**H9. Unescaped daemon configuration is an unsafe administrative interface. Verified:** Nginx site name, backend, hostnames and cert reference are raw text-template values (`proxy.go:749-779`), but validator checks only name nonempty, port and backend count (`validate_services.go:137-147`). Managed OpenVPN remote also enters directive text with only a nonempty check (`vpn.go:395-398,466`; `validate_services.go:379-404`), and profile import rejects only exact `daemon` (`vpn_service_handlers.go:156-174`). **Inferred:** crafted strings can add directives; a syntactically valid injected config may survive `nginx -t`, and arbitrary OpenVPN profiles are powerful admin-controlled daemon input, not “safe data.” Treat as privileged code/config and enforce directive-safe names/host:port/cert IDs and bounded profile features. Push-DNS values are IP-validated by the config layer (`validate_services.go:426-429`); raw manager interpolation alone is not evidence of an API DNS-injection path. Exploitability/blast radius not runtime verified; do not grant these APIs to vendor users. Admin already has appliance-shell authority, so do not market this as demonstrated unauthenticated RCE.

**H10. Identity/time predicates are not kernel enforcement. Verified:** snapshot compilation preserves `Identities` and `Schedule` (`pkg/cp/compile/compile.go:73-94`); Go evaluator checks both (`pkg/dp/rules/eval.go:149-155`). However nft `compileEntry` only emits zones/CIDRs/protocol and action (`pkg/dp/enforce/enforce.go:392-457`), and only ICS predicates trigger NFQUEUE (`:541-545`). Resolver is created in mgmt and passed to HTTP (`pkg/app/mgmt/mgmt.go:81-82`), not an engine identity feed; inspected normal ICS eval context does not populate identities (`pkg/dp/engine/policy_eval.go:119-143`). **Inferred:** a plain SSH/RDP/HTTP ALLOW narrowed by identity or maintenance schedule can become unconditional L3/L4 ALLOW on nft. Reject unsupported enforceable-policy combinations or implement a reliable enforcement bridge before using these fields for vendor/time restrictions. This finding is about non-IEC104 SRA predicates, not re-auditing IEC104 work in progress.

### Medium — access semantics, evidence and operator trust

**M1. Saved intent ≠ active enforcement. Verified:** VPN/proxy setters save running config then call runtime apply and return 200 with warning (`vpn_service_handlers.go:50-58`; `service_handlers.go:441-448,477-484`). Proxy setters call runtime apply without an engine argument. **Inferred:** especially for revocation, a successful “save” is insufficient evidence that listener/engine policy changed. Track desired/applied revisions and gate SRA grants on acknowledged enforcement; UI should show degraded/failure, not a green success toast.

**M2. Managed OpenVPN client relative files have no matching working directory. Verified:** config references `ca.crt`, `client.crt`, `client.key`, `auth.txt` (`vpn.go:467-473`); supervisor sets neither `cmd.Dir` nor `--cd` (`:238-242`). **Inferred:** startup from the mgmt default directory fails to locate files; **Open:** demonstrate in the documented image. Use explicit paths or daemon working directory; renderer-only tests do not prove connectivity.

**M3. Proxy controls overstate enforcement. Verified:** `allowedClients` is a model/display field (`config/config.go:176`; `cli/show_commands.go:135`), absent from generated enforcement; upstream chaining is explicitly only a template comment (`proxy.go:702-706`). Listen zones **do** compile into input rules (`compile/compile.go:382-405`), although daemon binds `0.0.0.0` and does not perform per-zone socket binding. Do not repeat the stronger/incorrect claim that listen zones have no enforcement. Reverse sites auto-open WAN input and have no end-user authentication gate. Reject unsupported controls or label them non-enforcing; test actual packet path/CONNECT before making confinement claims.

**M4. Administrative audit has important blind spots. Verified:** no `auditLog` calls in user create/update/delete/admin-password handlers (`api/http/users_handlers.go:39-151`) or self-password change (`auth_handlers.go:254-298`); SSH failed handshakes simply return (`sshserver/server.go:154-157`), successful sessions/CLI lines are logged, native shell transcripts are not (`:175-217,272-285,329-335`). Proxy access logs are status-only (`proxy.go:691,742-743`). **Inferred:** account takeover/offboarding and vendor actions cannot be reconstructed end to end. Add explicit redacted account/security-change outcomes and session IDs; never log passwords, private keys or unredacted CLI secrets.

**M5. Evidence loss is silent and records are weakly correlated. Verified:** audit persistence errors are discarded (`api/http/server.go:765`; SSH audit writes similarly); schema lacks structured remote address, grant/session/asset/recording reference, integrity chain and retention metadata (`audit/audit.go:8-18`, `audit/store.go:69-98`). Legacy/lab actor fallback can trust caller-supplied `X-User`/`X-Source` (`server.go:744-759`), whereas normal session auth sets the actor from DB. **Inferred:** audit outages are invisible; lab/static-token actor names are not authenticated identities. Add durable exporter/backpressure/health and trusted provenance; decide fail-close vs audited break-glass explicitly.

**M6. Network revocation is not active-session termination. Verified:** plain established flows are accepted before non-DPI policy entries (`pkg/dp/enforce/enforce.go:199-218`); conntrack kill exists separately. SSH uses background connection context and has no per-user termination registry (`sshserver/server.go:169-203`); `Close` only closes listener (`:133-137`). **Inferred:** deleting a rule/user or expiring a future lease must not be assumed to end an established shell or transport; broker, userspace flow cache and kernel conntrack need coordinated cleanup.

**L1. DNAT auto-accept is not individually asset-bound (hardening, not a proven bypass). Verified:** `compileDNATAccept` matches ingress zone, any `ct status dnat`, destination port and optional source, but not `DestIP`, original listen port or egress (`pkg/dp/enforce/enforce.go:294-330`); auto-accept precedes normal L4 rules (`:199-218`). Corresponding DNAT rules **do** check source CIDRs (`:359-368`), so two generated forwards alone do not establish an unauthorized-source bypass. **Inferred:** other DNAT producers or future broker rules could cross-match this accept. Bind to translated destination/original tuple and add integration tests before using it as an SRA asset boundary.

**M8. SNAT UI save silently removes port forwards. Verified:** NAT card submits only enabled/egress/source zones (`ui/app/nat/page.tsx:289-299`), parent directly posts it (`:105-123`), and handler replaces the full NAT object (`api/http/dataplane_ids_handlers.go:399-417`). **Inferred:** saving an unrelated SNAT setting deletes persisted remote publication rules. Preserve fields or use scoped PATCH. The NAT setter only persists; it does not apply engine policy, making “saved” distinct from active access.

**M9. Last-admin protection does not cover role demotion. Verified:** delete checks last admin (`users/store.go:386-394`); update allows any admin→view role change with no count check (`:350-378`). **Inferred:** UI/API can demote the final admin, leaving no normal management write authority. Enforce invariant transactionally for all mutations; existing SSH shells are not a safe recovery strategy.

**M10. MFA challenges/codes are replayable within validity. Verified:** login challenges have purpose/sub/expiry but no consumed nonce or password/security revision (`api/http/auth_mfa.go:94-122`); successful code verification issues a session without consumption (`:136-161`); TOTP validator stores no last-used counter (`users/mfa.go:75-87`). **Inferred:** a captured challenge+code can mint another session within its accepted time window; pending challenges survive password changes until expiry. There **is** per-IP sensitive-endpoint throttling (`api/http/server.go:203-204`, `util.go:23-43`), so “MFA has no rate limit” would be incorrect. Add account/challenge attempt budgets, one-time consumption and security-epoch binding; prefer IdP-backed phishing-resistant MFA for stronger exercises.

**M11. Login return URL permits external redirects. Verified source and targeted URL proof:** `ui/app/login/page.tsx:71-74` accepts any `next.startsWith('/')`; `//example.invalid/landing` passes and resolves off-origin. **Inferred:** crafted login links can redirect a successfully authenticated user to a phishing page; not token exfiltration by itself. Parse against current origin, require origin equality and a safe local pathname. Node proof below exercised URL semantics, not a browser/login integration.

**Additional PKI lifecycle debt (Medium, Verified/Inferred):** CA/server/client “ensure” functions return existing files solely on existence, not certificate expiry/key match (`openvpn_pki.go:44-45,91-92,147-148`). Sanitizing/truncating names can alias distinct submitted names (`:188-207`); stable immutable credential IDs are preferable to display-name-derived files. The download GET calls ensure/create and may mint credentials (`vpn_service_handlers.go:313-320`), making a nominal read a privileged mutation. Add rotation/expiry status, explicit POST issuance, idempotency and exact credential identifiers. These are not demonstrated remote exploits.

## 4. Ranked maturity gaps and target architecture

### 4.1 Prioritized gaps (Inferred recommendations)

1. **P0 — trustworthy enforcement and ingress assurance:** resolve H1–H10 and M1/M6/M8 before teaching that “MFA required,” “scheduled vendor access,” “TLS enabled,” “revoked” or “saved” guarantees the corresponding access property. Preserve explicit intentionally insecure exercises, but never silently fall into them. Strict SRA lab profile must disable lab bypass/static admin tokens/default credential exposure and require named accounts with no MFA enrollment grace before asset launch.
2. **P1 — named, durable least-privilege access grants:** asset ID/address, protocol/port, subject/vendor/sponsor, purpose/ticket, approver, validity interval, inactivity limit, session/transfer/recording policy and applied revision. No broad “vendor VPN can reach OT” default. Approver cannot approve own request; account/contract expiry and emergency offboarding must remove rights.
3. **P1 — actual brokered sessions, not management shells or generic NAT:** SSH, RDP, VNC and HTTP(S) adapters with destination credential isolation, target trust verification, per-session authorization and controls for command/clipboard/file transfer; live oversight and operator/user/timeout termination. HTTP auth proxy alone is not remote-desktop isolation; network DPI/PCAP cannot record encrypted GUI intent.
4. **P1 — lifecycle and evidence:** durable requests/grants/sessions, reconciliation after broker/engine/mgmt restart, acknowledged revocation, data-flow cache/conntrack removal and complete actor→approval→asset→protocol→session→recording linkage. Expose partial failures rather than recording successful revocation on receipt of an API call.
5. **P2 — federation, scalable vendor lifecycle and protected evidence:** OIDC groups/claims and phishing-resistant MFA, invitations/sponsor/expiry, immutable or integrity-protected recordings with access control/retention/export, credential vault/rotation, controlled transfers, multiple independent vendor/site tenants.

### 4.2 Responsibility split — recommended, not current implementation

**containd owns the network boundary:** zones/conduits; broker/connector-to-asset allowlists; VPN transport where needed; industrial protocol enforcement only on plaintext inspected links; required runtime revision/health; grant-bound network leases, flow termination and network events. It should expose a narrow machine-authenticated grant adapter, not give the broker an unrestricted management-admin JWT. Define revocation and restart semantics before implementing UI.

**An SRA broker owns human/application access:** federation/MFA; vendor sponsor/account lifecycle; request/approval; policy evaluation per human session; target credential injection; SSH/RDP/VNC/HTTP adapters; stream recording, supervisor view, transfer/clipboard policy and close-session acknowledgement. Evaluate an existing gateway first (e.g. Guacamole-compatible RDP/VNC/SSH transport plus an IdP and policy/approval controller); it is an integration candidate, **not** a verified turnkey approval/PAM implementation. A stock web gateway is not a substitute for the control plane.

**Site connector (optional later):** outbound mutually authenticated tunnel from the protected site to broker, no unsolicited inbound protected-asset ports. Scope it to fixed asset routes/protocols; do not expose a generic SOCKS tunnel. Its credentials must not be appliance-admin credentials. For a small local Compose lab, an unavoidable inline broker→containd→asset network path is simpler and more inspectable than inventing an outbound connector immediately.

**Enforcement contract:** authenticated broker request carries grant ID, subject/vendor, asset/protocol, policy revision, hard deadline and reason; controller returns an applied network lease ID/revision. Broker launches only after authorization **and** engine acknowledgement. Use bounded leases with engine-local expiry (controller outage must not leave permanent access); reconcile persisted grants on restart. Closing/expiry first prevents reconnect/new grants and then terminates broker stream plus associated engine flows/conntrack; record each acknowledgement and failure. A grant cannot silently outlive account disable or the approved window.

**Important shared-IP constraint:** many users originate from one broker IP. Firewall source-IP tags cannot distinguish them, so broker admission remains authoritative. Aggregate reachability must never grant another user the first user's asset right; isolate per-session network namespaces/connector identities when independent per-user network enforcement/kill is required. Revoke one session by its actual stream/flow identity, not by blocking the whole broker IP and disrupting unrelated OT maintenance.

**OT safety:** killing access must close the remote control channel without stopping the PLC/process. Demonstrate process continuity and controller autonomous operation after termination. Remote-desktop access to an engineering host can still pivot; constrain the host's downstream network, local tool/desktop rights and application roles. “HTTPS-only” is not “monitoring-only”: enforce HMI/PLC read privileges at the target or on inspectable protocol paths, never infer read-only from TCP/443.
