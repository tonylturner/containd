### P1 — correctness, operator trust and access boundaries

**U01 — Offline PCAP “Apply rules” sends an invalid API envelope (P1).**
- **V:** `ui/app/pcap/page.tsx:108-115` POSTs `{rules}` to `/api/v1/firewall/rules`; the handler binds **one** `config.Rule` and rejects missing `id` (`api/http/firewall_rule_handlers.go:35-45`). No array/batch branch exists. A selected nonempty set therefore still has no top-level ID and is rejected. Local UI types also use `ics.functionCodes`/`unitIDs` (`pcap/page.tsx:46-49,603-608`) while the real predicate uses singular `functionCode`/`unitId` (`pkg/cp/config/config.go:803-812`).
- **I:** The flagship analyze → suggest → apply training task cannot complete; preview can omit actual restrictions. Use canonical rule types and a supported transactional/batch apply interface (or explicitly controlled per-rule operation with partial-result reporting). This is a payload defect, **not** the separately owned commit-UX work.
- Validation owner: UI + HTTP API; assert exact payload and returned candidate rules from a real analysis fixture, including mid-batch rejection.

**U02 — Template previews read the wrong schema (P1).**
- **V:** `ui/app/templates/page.tsx:28-36,455-463` reads top-level `protocol`/`functionCodes` and displays `*` for missing codes. Preview API returns generated `config.Rule[]` (`api/http/template_identity_handlers.go:198-208`), whose predicates are nested `ics.protocol`/`ics.functionCode` (`pkg/cp/config/config.go:791,803-812`; generated examples `pkg/cp/templates/ics_protocols.go:57-89`).
- **I:** A constrained rule is taught/reviewed as blank protocol/wildcard codes; the preview is not a faithful explanation of enforcement. Share canonical API types, show all relevant predicates and distinguish absent from unrestricted. Tests need real-shaped response fixtures, not the UI's invented local type.

IPS is always active (`:600-606`); configured WG enablement becomes tunnel-up (`:615-625`); the event bucketer (`:559-564`) does not recognize actual `service.av.detected`/`service.av.block_flow`. ## 4. Ranked gaps against a mature training/containerized industrial firewall

These are **I/recommended product gaps** based on verified inventory, not implementation commitments. Product rank and defect urgency differ: repair trust/data-loss defects immediately while designing SRA first; do not build attractive access screens atop missing enforcement.

1. **Secure remote access as a coherent product, not just VPN settings.** A student/vendor needs “request approved access to this workload until this time,” strong identity/MFA, least-privilege destination/protocol grants, launchable approved sessions, conspicuous expiry and terminate/revoke controls. An instructor/operator needs requests/approvals, active sessions, attributable audit and recording playback/export. Current VPN and conntrack pages do not provide this; local MFA is only a foundation. **Backend-dependent**, with gateway/broker/recording/identity/grant lifecycle contracts missing from this UI route inventory. Coordinate with SRA audit; do not implement dummy “approved/recording” UI.
2. **Trustworthy observable truth.** No invented production graphs, zone blame, “all nominal,” configured-as-running or heuristic compliance labels. Unknown/stale/unsupported must be first-class and demo activity unambiguous. Scope engine/mgmt/service/tunnel health independently and show measurement windows/provenance. U03/U04/U09/U10 are prerequisite repairs for both SRA and teaching.
3. **Reliable student setup/edit/apply journeys.** Fix PCAP/template schemas, natural typing, preservation of drafts/config, partial-write reporting and real API contracts. Each training operation needs prerequisites, human-readable preview, exact affected resources, safe rollback/reset and an observable expected result. This complements, not replaces, separately owned rule commit work.
4. **An explicit learn → inspect → explain → enforce → verify loop.** Surface live learned profiles, discovered inventory reconciliation, rule generation, simulation consequences, allowed/blocked demonstrations and evidence-linked verification. Current offline PCAP + wizard + CLI are disjoint. Provide protocols/assets/rules/flows as one investigation, not unrelated tables. No need to invent appliance commissioning.
5. **Accessible, responsive task completion.** A keyboard student, magnified display or small laptop should be able to inspect an alert, configure a VPN peer and approve/revoke access. Native forms, semantic tables/dialogs, readable contrast/type, adaptable navigation/detail panels, reduced motion and textual topology are baseline functionality, not later cosmetic polish.
6. **Durable correlated evidence.** Time/range/server paging, saved views/search, event/alert/flow/session/asset/rule/user links, alert lifecycle, complete audit detail/export, freshness and loss/truncation indicators. Recording access/retention/redaction becomes a security-sensitive extension for SRA. Current list limits cannot support a whole class/lab investigation reliably.
7. **Training scenarios and instructor controls.** Versioned lab manifests, learning objectives, role-specific instructions, deterministic stimuli, assertions/explanations, checkpoints/reset and evidence worksheets.
