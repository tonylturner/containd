## 1. Inventory

### Policy and namespace enforcement
- **Verified:** `pkg/cp/compile/compile.go:19-25,27-120` validates config and compiles rules, NAT, local services and deterministic zone→device mappings. It retains identity and schedule predicates (`85-94`) and original rule order (`73-100`). `pkg/dp/rules/eval.go:130-163,206-223` supplies preview and first-match userspace evaluation.
- **Verified:** `pkg/dp/enforce/enforce.go:52-81,113-221` emits an inet table, input default-drop, forwarding default policy, IPv4 dynamic blocks, optional DPI queue steering and conntrack established/related accept. Kernel ordering is allow-first, then ID (`165-171`), unlike the userspace evaluator. Native L4 emission (`392-457`) has no identity/schedule conditions.
- **Verified:** NAT has masquerade, port forwards and source restrictions (`enforce.go:224-375`); DNAT also auto-accepts forwarded traffic (`294-330`). nft application is a single `nft -f -` subprocess (`666-681`); temporary blocks use separate nft subprocess calls (`703-759`). Compile begins with namespace-wide `flush ruleset` (`62`).
- **Verified:** `docs/mkdocs/policy-model.md:3-13` advertises zones, nft/eBPF, schedule and identity rules and preview. `docs/mkdocs/docker-compose.md` explicitly makes protection conditional on traffic routing through containd, warns about multi-homing bypass, and distinguishes Docker topology/IP ownership from appliance policy. This boundary is correct and must remain prominent.

### Interfaces, routing, capture and runtime
- **Verified:** interface model supports logical name/device, alias, zone, physical/bridge/VLAN, static/DHCP, gateway and local access flags (`pkg/cp/config/config.go:355-400`). Linux application creates bridges/VLANs and addresses/default routes (`pkg/dp/netcfg/interface_apply_linux.go:53-165,175-314`). Static/policy routing uses netlink, named gateways, metrics and tables; route ownership protocol 98 and rule priority range 10000–19999 (`netcfg/routing_linux.go:21-76`). Non-Linux paths are stubs, not native enforcement.
- **Verified:** ownership reconciles on events plus every 10 seconds (`pkg/app/engine/ownership_linux.go:91-169`). Runtime desired-state updates and HTTP apply endpoints live in `pkg/app/engine/interface_handlers.go:22-135`; management interface CRUD/assign/reconcile and routing endpoints in `api/http/interface_routing_handlers.go:17-420`.
- **Verified:** AF_PACKET is observational and discards returned decisions (`pkg/dp/capture/afpacket_linux.go:79-84`), default snaplen 2048 (`capture.go:190-197`). NFQUEUE overrides AF_PACKET when configured (`pkg/dp/engine/engine.go:139-148`), copies whole packets, queues at most 1024 and uses synchronous verdicts (`capture/nfqueue_linux.go:179-223`). It has panic recovery/rebind backoff and bounded consecutive failures (`103-172`), plus generation-aware completion/settlement (`inline_gen.go`).

Reconfigure waits for old consumers before swapping state (`224-297`). NFLOG registration failure produces a service event without disabling filtering (`333-365`). Flow states have five-minute idle timeout, sweep is traffic-triggered every 30 seconds, and generic flow map has no capacity check (`engine.go:554-662`). Protocol/top-talker counters are derived from decoded events, not all wire traffic (`engine/runtime_events.go:174-182`; `stats/stats.go:51-120`).

## 3. Bugs and debt found (ranked)

### High severity — correctness / protection boundary
1. **Host-IP loss plus destructive normal address apply (prior finding confirmed). Verified:** `pkg/dp/netcfg/interface_apply_linux.go:256-262` discards the host IP returned by `net.ParseCIDR`; `269-275` reparses network strings and installs that address. DHCP repeats it at `191-195`. `netlink_addr_linux.go:26-39,72-73` sends that IP as IFA_LOCAL/IFA_ADDRESS. E.g. `192.168.242.2/24` becomes `.0/24`. **Inferred:** loss of intended gateway identity and reachability. Worse, `279-293` sets replaceV4 for any desired v4, deleting unmatched existing addresses even with Replace=false. This directly contradicts `ownership_linux.go:119` and `docs/mkdocs/dataplane.md:14` “non-destructive” claims; recurring reconcile can remove Docker-provided `.2`. Needs Linux network-namespace regression; not exercised here.
2. **Kernel loses schedule/identity restrictions; live identity plumbing missing (prior confirmed/expanded). Verified:** `compile/compile.go:85-94` preserves restrictions, but `enforce/enforce.go:392-457` ignores them; `rules/eval.go:155,206-223` evaluates them. `engine/policy_eval.go:119-143` never attaches identities. Identity API only updates management resolver (`api/http/template_identity_handlers.go:25-52`; created in `pkg/app/mgmt/mgmt.go:81`); no generic dataplane resolver invocation found. **Inferred:** native L4 identity/window-restricted allow becomes unconditional on those predicates; userspace ICS identity allows instead cannot match. Especially important for secure remote access labs: policy form fields are not proof of enforcement.
3. **Policy precedence differs across kernel, userspace and preview (prior confirmed). Verified:** kernel sorts allow before deny, then ID (`enforce.go:164-171`) and queues ICS before ordinary L4 (`183-218`); evaluator respects original snapshot order (`rules/eval.go:153-157`). No explicit policy priority is modeled (`config.go:782-795`). Existing `TestCompileFirewallAllowsBeforeDrops` intentionally pins the kernel behavior and passed in this audit (one targeted test). **Inferred:** overlapping broad allow/narrow deny or mixed ICS/L4 rules can disagree between preview and wire. Decide one normative ordering before changing tests; do not simply reverse the kernel sort and lose intended exceptions.
4. **Namespace-wide rules destruction and temporary-block loss (prior confirmed). Verified:** `enforce.go:62` emits `flush ruleset`; `113-121` recreates empty block sets on each successful rules apply. **Inferred:** unrelated nft tables in a shared/host namespace are removed, Docker/CNI integration is unsafe, and active temporary blocks lose remaining TTL on commit/replay. Ordinary isolated appliance namespace does NOT flush the Docker host's different namespace; scope the risk correctly. Table-local atomic reconciliation preserving dynamic state is required before host integration.
5. **Port forwarding bypasses normal L4 deny policy. Verified:** `enforce.go:199-202` installs DNAT accepts ahead of ordinary rules; `294-330` matches ingress, DNAT status, destination port and optional source list, but not translated destination IP or a matching firewall allow. Config comment (`config.go:628-629`) and NAT UI tip (`ui/app/nat/page.tsx:59-61`) explicitly require a separate allow, which the implementation does not. **Inferred:** publishing a port can grant access despite a normal explicit deny. Narrow destination binding and specify whether port publish is policy or translation; preserve ICS inspection ordering.
6. **“Enforce” does not guarantee inline semantic inspection outside IEC-specific validation. Verified:** with QueueID=0, ICS predicates compile to L4 accept/drop (`enforce.go:402-414`; test `enforce_test.go:216-239`). AF_PACKET ignores current packet decision (`capture/afpacket_linux.go:83-84`), only later dynamic blocking can affect traffic. Generic `validateDataPlane` checks little beyond interface names/table chars (`config/validate.go:834-848`); strict queue prerequisites are IEC-specific (`validate_iec104.go`). Disabling DPI/decoder or exclusions skips inspection (`engine.go:469-478`). **Inferred:** choosing enforce mode alone can permit command bytes before a later block, or never inspect them. Require explicit observe/retroactive/inline modes and reject impossible enforcement configurations.
7. **Generic parser failures and handler panics are fail-open by design, not universal fail-closed. Verified:** invalid unmarked packets accept (`engine/us_packet.go:27-35`), stream errors are ignored for verdict (`82-88`; `policy_eval.go:111-113,208-214`), recovered panic accepts outside marked envelope (`us_packet.go:170-184`). Existing `TestCaptureHandlerRecoversPanics` passed and explicitly asserts this behavior. **Inferred:** malformed/unsupported traffic can evade semantic allowlists on generic ICS paths. This is a product contract/failure-profile gap, not a claim that every malformed packet exploits a decoder. IEC-specific stricter behavior is in progress/out of this re-audit.
8. **Save/apply can report success while enforced policy is stale, and retry considers warnings applied. Verified:** `api/http/server.go:604-618,643-663` treats infrastructure errors and every `nft apply failed` as warnings; engine only swaps snapshot after successful nft apply (`engine.go:411-425`). `pkg/app/mgmt/engine_sync.go:115-125` sets applied=true even with warnings, suppressing same-boot retry. **Inferred:** persisted desired policy and actual kernel/evaluator state diverge after transient nft failure; no automatic retry until boot/rollback trigger. Keep demo-mode warnings, but distinguish “saved,” “partially applied,” and “protecting,” retain last-good revision and retry convergence.
9. **No generic flow/stat cardinality budget. Verified:** `engine.go:619-623,646-661` inserts generic flow states without cap; sweep only occurs on arriving traffic (`554-568`) and idle timeout is five minutes. `stats/stats.go:90-98,113-120` grows flow map without expiry. **Inferred:** flow/endpoint churn can exhaust memory or stall global-lock sweeps in a long classroom run or hostile container workload. Bounded stream/cache/event structures do not bound aggregate memory.

### Medium severity — semantics, lifecycle, evidence
10. **IPv6 acceptance exceeds support (prior confirmed/expanded). Verified:** rule/interface validators accept CIDRv6 (`validate.go:307-310,374-380`), but nft always uses `ip saddr/daddr` (`enforce.go:444-450`), block updater rejects v6 (`704-713`), default gateway only v4 (`netcfg_linux.go:76-78`), reset and conntrack kill only v4. Routing CIDRv6 is accepted (`validate.go:771-773,820-827`) but route builder emits AF_INET and `.To4()` destination (`routing_routes_linux.go:71-81,134-148`), while PBR explicitly errors. Input chain has no ICMPv6/ND allow (`enforce.go:124-145`). **Inferred:** invalid apply, broken v6 connectivity or zone-only allows without address-level parity; an inet table is not dual-stack assurance.
11. **Route removal is not convergence; reconcile ownership is incomplete. Verified:** normal `applyRouting` only adds (`routing_linux.go:31-76`); API save/delete reapplies additive config (`interface_routing_handlers.go:359-385`; CLI `routing_set.go:272-293,342-363`). Replace deletes all protocol-98 routes and priority-range rules before installing desired state. Explicit priorities are accepted outside 10000–19999 (`validate.go:811-818`) but `decodeManagedRule` only owns that range (`routing_rules_linux.go:263-266`). **Inferred:** deleted routes/PBR may remain until explicit reconcile, out-of-range rules can survive even replace, and unrelated rules in range can be removed. Add ownership-aware diff, deletion and rollback rather than delete-all-first.
12. **Temporary “flow” block key is not transport/session-specific. Verified:** `block_flows` type is src-IP . dst-IP . destination-port (`enforce.go:118-120`); matcher accepts both TCP/UDP (`162`); updater validates proto then drops it from key (`711-725,738-745`). Source port is also absent. **Inferred:** denied TCP service can block UDP on the same port and all client connections to the same endpoint pair; key/documentation/API promise must agree. No block-list/unblock API was found in registration inventory.
13. **Preview is not a wire-accurate policy oracle. Verified:** nft preview uses a default new compiler without configured table/queue/NFLOG (`api/http/dataplane_ids_handlers.go:44-50`). Historical match preview builds IP/proto/port/time only (`firewall_rule_handlers.go:274-285`), omitting zones, identities and generic ICS attributes; only IEC-specific augmentation exists. **Inferred:** zoned, identity or generic ICS rules can show zero sample matches even when applicable, and displayed nft differs materially from actual inline rules. Must expose limitations or share a canonical compile/context builder.
14. **eBPF docs advertise a stub; dormant correctness defects. Verified:** `docs/mkdocs/ebpf.md:3` and `policy-model.md:3` promise optional acceleration/counters/event streaming. Programs return PASS/OK, do not consult maps/update stats (`ebpf/xdp.go:37-52`, `tc.go:44-63`); app uses nft updater. `tcMapSpecs` returns KeySize=8; init changes a discarded temporary map to 12 (`tc.go:24-42`), unlike 12-byte `bpfFlowKey` (`types.go:26-32`). TTL reap explicitly unimplemented (`updater.go:49-52`), map sync delete-first and ignores delete/iteration errors (`loader.go:202-215,244-253`); TCX attachment has no claimed older-kernel fallback (`tc.go:66-80`). **Inferred:** wiring this as-is would falsely report successful nonblocking host blocks, fail flow key writes, or create nonexpiring blocks after a real program exists. Retire feature claims now; implement only after nft baseline is trustworthy.
15. **Verdict evidence is not complete or immutable policy proof. Verified:** native log only for explicit Log rules with NFLogGroup (`enforce.go:423-425`); dynamic/default/established accepts/drops have no per-rule logging/counter there (`149-221`). Prefix sanitization/truncation loses identity (`494-518`), and consumer stores only sanitized ID/action/tuple (`capture/nflog_linux.go:125-164`). Generic decision event has no policy revision or applied-vs-would-block field (`engine/runtime_events.go:338-375`); event store in live application is a 4096 ring, not spill-enabled (`pkg/app/engine/engine.go:92-93`). **Inferred:** operator cannot reliably reconstruct exact rule/revision/reason for every enforcement outcome; IDs can collide after truncation. NFLOG receive errors are discarded by engine callback (`engine.go:341-344`). Use bounded/rate-limited structured decision evidence and loss metrics, not payload logging for every packet.
16. **Readiness is process-presence, not protection readiness. Verified:** `/readyz` tests dpEngine != nil (`pkg/app/engine/engine.go:142-147`), config endpoint returns configured before asynchronous start (`config_handler.go:90-95`); AF_PACKET Start launches workers without waiting for successful raw-socket bind (`capture.go:200-213`). **Inferred:** orchestration can route workloads before queue/capture/rules are ready; healthy HTTP alone does not mean enforced revision or required forwarding exists. Liveness/readiness/degraded must be separate; IEC health is not generic readiness.
17. **Bridge/VLAN lifecycle and filtering assumptions are unfinished. Verified:** virtual interfaces/members are created/attached (`interface_apply_linux.go:73-140`), no reverse detach/delete reconciliation exists in that path, and firewall only emits inet hooks (`enforce.go:63,124-221`). No bridge-family rules or bridge-netfilter requirement/preflight found. **Inferred:** removing a configured member may leave L2 forwarding relationships; transparent filtering depends on external kernel bridge settings. Require topology/bridge namespace tests before advertising transparent firewall behavior.
18. **“Kill session” deletes conntrack, not a durable revocation. Verified:** handler invokes conntrack.Delete only (`runtime_handlers.go:264-276`), no corresponding temporary block or general reset call; frontend correctly says best-effort (`sessions/page.tsx:87,147`). **Inferred:** endpoint TCP state can remain, loose conntrack can reacquire traffic, and reconnect is not prevented. SRA termination must revoke policy/identity plus close proxy/tunnel/session, not reuse this endpoint as an assurance.
19. **Statistics overcount bytes/packets and misclassify unknowns. Verified:** per event, `recordProtoStats` records full packet payload length (`runtime_events.go:174-182`), while `stats.Record` increments PacketCount and EventCount together (`stats.go:69-71`), defaults non-alert/non-write to ReadCount (`74-84`), and can also record same flow via event src/dst (`86-98`) before explicit RecordFlow. **Inferred:** multiple events per packet inflate byte/talker counts; unknown/malformed isn't necessarily read. Label event-derived estimates, count wire bytes once, and represent unknown semantic direction.
20. **Domain exclusions are accepted but ignored. Verified:** schema exposes domain exclusions (`config.go:495-500`), UI lets them be configured, but `engine/policy_eval.go:54-60` simply continues. **Inferred:** operator-requested exemptions do not behave as expected. Reject unsupported type or implement metadata-aware documented semantics; do not silently accept.
21. **Ownership netlink subscription mask is wrong. Verified:** `ownership_linux.go:181-191` ORs RTNLGRP ordinal constants directly into SockaddrNetlink.Groups instead of bit masks `1 << (group-1)`. **Inferred:** address/route change events are missed or wrong groups subscribed; 10-second periodic reconcile partly masks this. Also Recvfrom is blocking and not context-interruptible (`204`), so watcher shutdown may linger. Correct subscriptions and test event-driven drift recovery.
22. **Conntrack backend absence masquerades as empty; route device absence is tolerated. Verified:** `/proc` missing/permission failures return empty nil (`conntrack_linux.go:21-35`), UI cannot distinguish absent backend (`sessions/page.tsx:134-137`). `routeInterfaceIndex` returns 0 for a nonexistent interface (`routing_routes_linux.go:107-115`) rather than rejecting it, omitting OIF in request. **Inferred:** diagnostics may look healthy or route via an unintended interface when configured device vanishes. Prefer netlink conntrack capabilities/status and strict resolved-device preflight.

Fail the read before writing.
24. **Docs overstate implementation beyond eBPF. Verified:** `docs/mkdocs/dataplane.md:8` points at nonexistent `pkg/dp/reassembly` (actual `pkg/dp/dpi/reassembly.go`); line 20 lists reset/tag/rate-limit and conntrack updates, while generic `applyVerdict` implements only host/flow temporary blocks and otherwise nil (`engine/runtime_events.go:403-418`). Constants alone (`verdict/verdict.go:15-27`) are not working actions. `docs/mkdocs/policy-model.md:5` says assets/policy objects though actual Rule contains CIDR lists only (`config.go:782-795`; compiler only expands vpn:* tokens at `compile.go:172-198`). 25. **Dev deployment boundary is weaker than starter. Verified:** `deploy/docker-compose.dev.yml:84-86` mounts Docker socket and its interior network definitions (`132+`) lack starter `internal: true`; starter publishes management ports to unspecified host address (`docker-compose.yml:109-112`). **Inferred:** dev compose is not interchangeable with a protected-workload reference, and read-only socket bind is not authorization for Docker API requests. Cross-area security/deployment owner should remove unnecessary socket access and document exposure; no Docker runtime was accessed here.

### Additional cross-cutting findings
26. **Medium — NAT contains fixed wan→lan zone references. Verified:** `enforce.go:279-280` emits `@zone_wan_ifaces` and `@zone_lan_ifaces` whenever any port-forward entry exists and NAT is enabled, regardless of configured egress/source zones or whether entries are enabled. Validation only checks configured zone references (`validate.go:465-490`). **Inferred:** legitimate custom-zone deployments (or starter lan1..lan6 without a lan set) can fail whole-ruleset application; ordinary “hairpin” NAT should derive actual ingress/egress/destination policy, not hardcode names. Existing NAT test only uses wan/lan (`enforce_test.go:414-457`) and cannot catch it.
27. **High for revocation use cases — Ordinary policy change does not revoke existing L4 sessions. Verified:** established/related accept precedes ordinary rules (`enforce.go:199-218`); ApplyRules stores a new snapshot but does not remove conntrack or flush/revision-key generic verdict cache (`engine.go:407-425`). **Inferred:** replacing an allow with deny does not stop an already-established L4 conversation; cached generic deny can also persist briefly after an allow change, and dynamic blocks disappear on reload (#4). This can be a deliberate connection-preservation policy, but is currently not an explicit per-change revocation choice. Secure remote access expiry/offboarding requires stronger semantics than “new connections denied.”

28. **Medium — Disabling enforcement leaves the old kernel rules behind. Verified:** Reconfigure replaces compiler/updater with nil when enforcement is disabled (`engine/engine.go:183-209,260-263`); ApplyRules then skips nft entirely (`411-419`). No teardown of the previously installed table occurs in that path. **Inferred:** observe-only can still block traffic using stale rules; status may show no compiled rules even though old hooks remain. Define and test ownership-safe disable semantics (remove owned policy vs explicitly retain protection), and display the actual active state.

## 4. Ranked gaps vs mature training/containerized firewall

1. **P0 — truthful protection contract and parity.** The largest gap is not more protocol names: operator intent, preview, userspace verdict and kernel rules must mean the same thing. Fix addressing and table ownership first; settle precedence, DNAT firewall policy, unsupported identity/schedules, established-flow revocation and generic semantic enforcement prerequisites. Training exercises must demonstrate actual server non-actuation, not just a deny event.
2. **P0 — enforced-state convergence and safe failure modes.** Desired/saved/applied/protecting need distinct revisions and health. Startup, transient nft errors, no queue listener, queue overflow, disabled decoder, malformed data, process crash, policy replay and partial routing failures need explicit observable outcomes. Support a deliberate permissive training/observe profile and stricter inline profile; never silently substitute one for the other.
3. **P1 — unavoidable Docker packet path.** Starter networks alone are not the security boundary. Ship a small supported topology with mandatory gateway routing and tests for same-network peers, alternate networks, published ports/direct addresses, return path, IPv6 and namespace sharing. One container attached to both zone networks is a bypass regardless of rules. Network membership/route intent must be auditable alongside policy.
4. **P1 — SRA integration, not SRA reinvention.** Expose enforceable short-lived access grants tied to authenticated identity/session, policy revision, asset/protocol and expiry; removal must stop current traffic. An IP→name map is not user authentication and mutable container addresses are not durable identities. Connect to the priority SRA broker/VPN owner; require approval/MFA/session termination upstream and correlate dataplane evidence downstream. Existing firewall schedule/identity fields must not be sold as PAM.
5. **P1 — resource/latency/diagnostic maturity.** Bound all aggregate state and asynchronous work; publish queue depth/kernel loss/parser failures/capture readiness/block failures/applied revision. Benchmark compile/apply at 10/100/1000/10000 rules and realistic flow churn/long sessions/mixed traffic; report p50/p95/p99 latency, throughput, CPU/memory and actual first-write prevention on Linux Docker and Desktop separately. Current microbenchmarks are useful regression probes, not capacity evidence.
6. **P1 — evidence that distinguishes decision from actuation.** A would-deny event, AF_PACKET retroactive block, inline drop and server non-actuation are different assertions. Correlate rule/revision/session/tuple/NAT transformation/reason/mode/queue generation with bounded durable evidence and explicit loss counters. Keep secrets/payload out by default.
7. **P2 — dual-stack or explicit v4-only guardrail.** Prefer hard rejection/documented disablement of unsupported IPv6 in the short term; full parity needs CIDR-family compilation, ICMPv6/ND/PMTU, routing/PBR, blocks and session control. Test mixed-family inputs and IPv6 bypass; no blanket “inet means supported.”
8. **P2 — orchestration identities and Kubernetes-adjacent traffic steering.** Reconcile Docker name/label→endpoint lifecycle with stale-IP cleanup before an opt-in CNI gateway controller. NetworkPolicy/Cilium/Calico should force the path and supply selectors; containd supplies industrial semantics. Do not attempt a replacement CNI, import a Docker socket into the dataplane, or claim pod protection before real bypass/failure tests.
9. **P3 — optional acceleration / virtual resilience.** eBPF should remain honestly marked unavailable until real maps/programs, TTL semantics, fallback parity and kernel tests exist. Virtual multi-instance failover/state handoff may be useful for training failure drills later; physical bypass hardware, ISO/appliance packaging and production interface certification are non-goals.
