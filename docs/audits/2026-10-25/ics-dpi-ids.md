# ICS / DPI / IDS maturity audit

Audit date: 2026-10-25. Target: `iec104` at `40ec7f81` (clean checkout at start), containd 0.1.32 / next 0.1.33. Read-only source review for testing/training and containerized-workload protection, not physical-interface production certification. Prior interrupted report was read; its claims were independently verified and carried forward below. Benchmarks comparison: area 2 (industrial inspection/detection). **Verified** means source/test inspected, not necessarily executed. **Inferred** marks operational consequences. No Docker, GUI, whole-package suites, pushes, commits or source edits.

Excluded: IEC104 monitor-type expansion, IEC rule preview/mode display, and IEC evidence retention/query: **in progress**, not re-audited here. Shared IEC transport/predicate architecture is referenced only to explain coverage and integration. Secure remote access is the overall product priority; this area's roadmap prioritizes trust in lab detections before broad new protocol work.

## 1. Inventory

### Scope and evidence method

Inventory includes all decoder families in `pkg/dp/ics`, `pkg/dp/itdpi`, DPI stream handling, predicates, IDS import/evaluation, signatures/Sigma, learning, anomaly, inventory, synth, offline PCAP and event/export consumers. API, CLI, UI and docs are cross-checked separately below. Tests inspected are not claims of test execution. No performance benchmark or wire-interoperability certification is implied by parser unit tests.

### Decoder and policy inventory (Verified)

- Registry: eight industrial decoders, eight detailed IT metadata decoders plus two utility decoders (`pkg/dp/engine/decoders.go:23-43`). Per-protocol disable maps exist; utility decoders remain enabled (`:68-94`). All production parsers are local Go implementations, not Suricata/Zeek engines.
- Stream contract/reassembly: `pkg/dp/dpi/dpi.go:13-16,35-69`, `inspect.go:27-95,115-161`, `stream.go:22`. Only Modbus, DNP3 and IEC104 implement framed stream parsing; other TCP decoders receive one captured segment. Shared feed/parse/trim is mutex-serialized, validates contiguous frame contracts, and reports malformed/bounds/overlap errors. This is a substantial foundation, not universal stream coverage.
- Modbus/TCP: MBAP length framing, multi-ADU/split parsing, function/unit/transaction, exception/diagnostic/MEI classification and capped raw hex (`pkg/dp/ics/modbus/modbus.go:36-75`, `decoder.go:42-72,94-161`). Numeric address/quantity extraction is best-effort, not full request/response semantic validation.
- DNP3/TCP: validated link-header CRC and length, block stripping, application FC, link direction, IIN, object-group/qualifier/count walking with fixed/packed/size-prefixed object tables (`pkg/dp/ics/dnp3/link.go:27-96`, `decoder.go:44-78,101-170`, `objects.go:37-71,125-195,197-244`). No application-fragment reassembly or data-block CRC validation.
- CIP/EtherNet/IP: EIP encapsulation, SendRRData/SendUnitData CPF, service/path/class/instance/attribute, MSP subservices, read/write/control (`pkg/dp/ics/cip/decoder.go:21-163`, `frame.go:125-157,169-244,246-336,339-441`). Packet-only; UDP/2222 goes through the EIP-encapsulation parser rather than a dedicated implicit-I/O decoder. Connected/response layouts need correction (findings below).
- S7comm: TPKT/COTP, classic S7 header/FC, first ReadVar/WriteVar item, area/DB/address, stop/control/download and ACK errors (`pkg/dp/ics/s7comm/decoder.go:36-161`, `frame.go:180-219,271-324`). No S7comm-plus or session/fragment reconstruction.
- IEC61850 MMS: TCP/102, TPKT/COTP separation from S7, simplified BER service scan, read/write/control and first domain-specific variable name (`pkg/dp/ics/iec61850/mms.go:84-164,183-234,259-331,368-460`). Does not implement the full ISO session/presentation/ACSE stack or GOOSE/Sampled Values.
- BACnet/IP: UDP/47808 BVLC/NPDU/APDU service, discovery, object/property and critical-service metadata (`pkg/dp/ics/bacnet/decoder.go:20-95`, `frame.go:118-154,206-241`). No BACnet/SC, MS/TP or segmented APDU assembly.
- OPC UA Binary: TCP/4840 message/chunk header and numeric service NodeId at fixed offset, session/read/write classification (`pkg/dp/ics/opcua/frame.go:95-175`, `decoder.go:36-86`). No secure-channel policy tracking, decryption, chunk reassembly, node-level authorization or PubSub inspection.
- IT: DNS query/response first-question metadata and bounded compression parsing (`pkg/dp/itdpi/dns.go:36-105,112-194`); HTTP/1 method/path/host/target/user-agent and 4 KiB preview/hash plus HTTP/2 preface only (`http.go:45-164`); TLS ClientHello SNI/ALPN/cipher/extensions and approximate JA3 (`tls.go:47-94,108-175,245-266`); SSH banner and first offered KEX/encryption algorithms (`ssh.go:40-55,60-132,150-225`); SMB1/2 headers/commands/share (`smb.go:69-171,177-208`); NTP version/mode/stratum/risk (`ntp.go:48-117`); SNMP1/2c PDU/error/first OID and v3 security-model metadata without community disclosure (`snmp.go:69-103,108-133,195-205,255-289`); RDP X.224/cookie/security negotiation/MCS marker (`rdp.go:67-109,115-225`). All are packet-local, port-selected metadata visibility, not application-session monitoring or remote-access control.
- Utility: `ICSMarker.OnPacket` is intentionally a no-op; pipeline calls `MarkICS` separately (`pkg/dp/itdpi/ics_marker.go:20-42`). PortDetector emits unverified `detect` events per packet (`detect.go:21-77`); port guesses must not be represented as decoded evidence.
- Firewall semantics: immutable snapshots; first-match zones/CIDRs/transport/identity/schedule plus generic ICS protocol, FC, unit, numeric address, CIP class, direction and read/write (`pkg/dp/rules/rules.go:59-104`, `eval.go:88-127,149-162,226-308`). Runtime mapping only reads `function_code`, `unit_id`, `object_class`, `address`, `is_write` (`pkg/dp/engine/policy_eval.go:111-143`). Broad protocol-specific UI/doc claims exceed this shared context. Non-IEC preventive deny is dynamic-block based, with no universal message holdback (`policy_eval.go:66-108`; milestone B §4.1 explicitly limits split-message protection).

### Detection, discovery and training inventory (Verified)

- Two distinct alert systems: native/imported IDS condition trees (`pkg/dp/ids/evaluator.go:42-70,126-229`) and ICS signatures with AND predicates, bounded 4096 match history and optional per-flow thresholds (`pkg/dp/signatures/signature.go:18-55,117-171`, `threshold.go:13-91`). The latter has 16 non-IEC builtins spanning Modbus, DNP3, CIP, S7 and a generic write signature (`builtins.go:17-207`), plus IEC builtins. Custom signature JSON validation checks ID/conditions/threshold only (`custom.go:21-50`); no operator/field/regex validation or duplicate-ID rejection.
- Import/export: Suricata/Snort shared syntax parser, Sigma subset with boolean selections, YARA metadata/string preservation, format detection/export, rule-source URL/license catalog (`pkg/cp/ids/convert.go:15-96`, `suricata.go:84-110`, `snort.go:10-26`, `sigma.go:18-112`, `sigma_detection.go:15-143`, `yara.go:16-90`, `sources.go:12-69`). This is conversion/storage, **not equivalent execution** of these engines. Native JSON backup/restore is a separate HTTP path.
- Passive learning: per-direction IP-pair/protocol observed FC/unit/address/read-write sets with generation of ALLOW rules (`pkg/dp/learn/learner.go:18-45,48-73,94-168,235-286`). No persistence, confidence window, accepted-baseline lifecycle, cardinality limit or expiry in this structure.
- Anomaly: deterministic malformed/protocol/rate checks, Modbus request tracking, DNP3 restart, S7 stop/download, CIP mode-change intentions, cross-protocol/nonstandard-port checks; 4096 recent anomalies (`pkg/dp/anomaly/detector.go:86-146,153-245,446-620`). Not process-physics or statistical behavioral modeling; thresholds default globally to 100 writes/1000 operations per minute.
- Inventory: in-memory IP-keyed Modbus/DNP3/CIP assets, peers/FC/unit/station addresses/roles (`pkg/dp/inventory/inventory.go:15-55,58-174`). Not an all-decoder device catalog, vendor/model fingerprint or container/workload identity inventory.
- Synth: weighted metadata event generator with configurable subnet prefixes and rate, wall-clock RNG seed, direct event-store append and callback (`pkg/dp/synth/generator.go:24-40,112-143,169-230`). It does not generate wire traffic; it cannot prove parser or inline-enforcement correctness.

### PCAP, event/export and user interfaces (Verified)

- Offline analysis: Ethernet (+ one 802.1Q), IPv4/IPv6 using shared capture decoding, directional flow summaries, decoded-event totals, PCAP-to-policy via a fresh learner (`pkg/dp/pcap/analyze.go:52-97,115-198,228-254,306-329`). Results are unbounded arrays/maps for the entire input. API analyzes in the management process, not via an engine analysis RPC (`api/http/pcap_handlers.go:303-365`). Decoder errors are discarded after events; analysis does not run the live anomaly/signature/IDS/inventory pipeline despite the docs claiming inventory updates.
- Event model: raw DPI event has FlowID/Proto/Kind/map attributes/time (`pkg/dp/dpi/dpi.go:35-42`); stored telemetry adds ID, endpoint tuple, transport, hash (`pkg/dp/events/store.go:21-54,209`). General bounded ring defaults to 4096 with optional asynchronous JSONL overflow spill, 50 MiB rotation and five rotated files (`store.go:56-104,107-207`, `ring.go:14-33`). General flow view is a ring-derived rollup, not a durable session table (`store.go:350-404`). IEC-specific retention/query is in progress and excluded.
- Live fanout: normalize → inventory/learner → anomaly/signatures → AV/statistics → raw event → native IDS alerts (`pkg/dp/engine/runtime_events.go:28-43,60-134,185-199`). Separate custom signatures and native IDS mean “IDS enabled” is not an all-detectors master switch.
- Export library: CEF, JSON-lines, RFC5424 wrapper, file/UDP/TCP sinks/filter (`pkg/dp/export/export.go:15-18,52-91,101-174`, `exporter.go:22-105`, `sink.go:27-149`). `config.ExportConfig` exists (`pkg/cp/config/config.go:503-509`), but repository search finds **no production import/use of pkg/dp/export, cfg.Export, or NewWithFilter**. Rate as library-only/stub integration, not a working configured SIEM feature. This materially strengthens the prior report's export finding.

## 3. Bugs and debt (ranked trust-breaking findings, then supporting debt)

Severity reflects trust, policy fidelity, training correctness and bounded operation in container labs. **High** is not a claim of demonstrated remote exploitation. Reproduction probes assert the *observed defective behavior*; passing them confirms a defect, not product acceptance. File references are checkout-relative.

### Incorrect policy, detection and successful-looking workflows

**D01 [High] — Non-IEC address predicates silently disappear; protocol-specific selectors exceed the execution model.** **Verified + targeted reproduction.** `pkg/cp/config/validate_ics.go:17-42` validates protocol/mode but not non-IEC address syntax. `pkg/dp/rules/eval.go:94-109` discards unparseable addresses; `:269-282` treats an empty compiled set as unrestricted. A validated/compiled CIP ALLOW restricted to `0x04/10/3` allowed unrelated `0x99/99/99` in the audit probe. This is fail-open broadening, not merely a form-validation omission. Runtime maps only generic `function_code`, `unit_id`, `object_class`, `address` (`pkg/dp/engine/policy_eval.go:111-143`): BACnet emits `service_code` without `function_code/address` (`bacnet/decoder.go:58-69`); MMS emits string service tags/variable names (`iec61850/mms.go:211-224`); OPC UA emits service names (`opcua/decoder.go:64-75`). **Inferred:** several FC/address options cannot enforce their advertised semantics, while absent FC defaults can match zero. Reject unsupported fields/values at validation/compile boundaries; do not silently drop restrictions. UI labels in `ui/app/ics/ics-shared.ts:14-92` and `firewall/firewall-utils.ts:21-124` must follow actual protocol contracts.

**D02 [High] — Import compatibility can produce universal alerts, silent misses and false evidence.** **Verified + targeted reproduction.** YARA creates no condition/protocol/disabled state, labels itself `evaluable=false` (`pkg/cp/ids/yara.go:34-44,73-88`); compilation retains it (`pkg/cp/compile/compile.go:122-166`); evaluator ignores the label, defaults nil Enabled to active, and empty conditions match every event (`pkg/dp/ids/evaluator.go:57-70,126-129`). Probe: imported YARA alerted on unrelated benign DNS. Suricata/Snort addresses, ports, action, payload contents, offsets, flowbits and thresholds are preserved metadata, not enforced predicates; raw header direction is discarded (`suricata.go:135-147`; evaluator `:57-70`). Sticky HTTP/DNS/TLS conversion uses `attr.http_uri/http_method/dns_query/tls_sni` (`suricata.go:420-481`) rather than decoder `path/method/qname/sni`. Probe: a decoder-shaped event with `path=/evil` did not match the imported URI rule (the probe constructs this event; the real decoder field name was source-verified). Generic `tcp` rules may never match application-protocol events; port aliases include `enip` instead of `cip`, shared TCP/102 forced to S7 and no IEC2404 mapping (`suricata.go:16-25,165-180`). Conversion notes call content/flow/threshold/flowbits “fully handled” (`:491-499`), hiding loss. Alerts populate `matched_patterns` with **all stored patterns without evaluating them** (`evaluator.go:112-123`). **Inferred:** severe false-positive/negative and evidence-integrity problems. Make storage-only rules non-executable and reject lossy activation; display explicit capability/loss status, never infer compatibility from parse success.

**D03 [High] — Self-consistent fixtures hide wrong X.224 bytes in S7 and RDP.** **Verified code/fixture mismatch with the correct constants already used elsewhere; real-wire consequences inferred, not executed.** S7 compares raw COTP byte to `COTPData=0x0F` (`pkg/dp/ics/s7comm/frame.go:37-42,163-177`, `decoder.go:51-56`); fixture builders and assertions also use `0x0F` (`decoder_test.go:26-29,119-126`). Normal DT type is `0xF0`, as containd's MMS parser itself declares and masks (`pkg/dp/ics/iec61850/mms.go:24,164`). Thus normal S7 DT traffic does not reach service decoding. ## 4. Ranked maturity gaps vs the training/container product

1. **Trustworthy executable contracts, not import/decoder name breadth.** Highest priority: never turn an unsupported constraint into ANY, unknown into read, a storage-only rule into a detector, or a discarded conversion into success. Existing cross-layer tests mostly verify shapes, not semantics. D01–D06/D08/D10/D11/D14/D24 are immediate blockers to teaching reliable allowlisting/detection outcomes.
2. **Independent wire-conformance and negative corpus.** Add real stack/capture-derived request/reply/error fixtures with expected commands, addresses, negative rules and incomplete/unsupported states; test split/coalesced/OOO/retransmitted forms. S7/RDP wrong-byte fixtures demonstrate why synthetic builders cannot be their own authority. For OPC UA, encryption boundary and Binary encoding IDs must be explicit; for CIP, connected/MSP/response profile explicit. No mature claim should depend on unexecuted vendor-interoperability assumptions.
3. **One canonical, versioned detection/event contract across live/offline/demo/API/UI/export.** Extend the **existing** `pkg/dp/ics/eventfields` strict accessors and decoder-test utilities rather than inventing a parallel registry. Include protocol IDs, endpoint/session identity, observation time vs processing time, severity, source/provenance, inspection-completeness/opaque status and rule match evidence. This unlocks honest alert feeds, stable Sigma subset, inventory, policy learning and export.
4. **Safe learning → reviewed exact policy → explicitly activated configuration.** A mature lab needs reproducible baseline windows, drift/candidate diffs, exact observed constraints, rejection of ambiguous unsupported selectors, validation by replay/negative mutations and explicit deployment state. It must never promote hostile/untrusted observations to automatic enforcement without review. Fix payload/role/save/apply contracts before adding a wizard.
5. **Useful container-aware discovery and lifecycle bounds.** Multiservice/multiprotocol peers and short-lived container IP reuse are normal, not anomalies. Need workload/zone/session identities, endpoint direction, asset protocol sets, observation confidence and bounded expiry. Existing per-stream limits/rings are a good start; aggregate state budgets, overload/drop metrics and concurrency tests remain necessary even for noisy/fuzzing training labs.
6. **Reproducible training and offline parity.** A seeded, clearly synthetic demo is useful, but assessment should use vetted wire scenarios and the same detection semantics as live traffic. Include benign lookalikes, command variants, segmentation, malformed inputs and expected false-positive/negative assertions. Offline analysis must preserve capture time and report corruption/unsupported formats rather than quietly succeeding.
7. **Reliable security-event delivery and evidence fidelity.** Wire supported asynchronous exports only after protocol/alert filters, severity, framing, endpoint preservation, authenticated encrypted transport, explicit loss/backpressure and privacy controls are specified. General event-ring provenance/loss improvements must not duplicate the IEC-specific evidence work in progress.
8. **An honest, task-oriented operator surface.** Show capability and parser confidence, storage-only imports, rejected constructs, saved vs applied state, detector availability and useful detail. Unify discovering → learning → reviewing generated policy → observing signature/anomaly results. Add headless contract/role tests and later browser accessibility/keyboard tests; this audit makes no aesthetic score.
9. **Prioritized additional protocols/content supply.** MQTT is a plausible next routed container lab protocol; add only on confirmed scenario demand. More complete existing CIP/S7/OPC UA/MMS semantics likely yield more immediate value than nominal GOOSE/Profinet coverage. Industrial feed curation needs supported-field profiles, update provenance, version/license verification, tested packs and rollback; the current sources URL catalog is not feed lifecycle management.
10. **Secure remote access alignment without scope confusion.** Correct RDP/SSH/TLS event schemas and preserve identity/session correlation so the separate SRA work can consume trustworthy telemetry. Passive RDP/SSH decoding is not a bastion, MFA, approvals, time-bound vendor access or session recording. Those product capabilities belong to the SRA lane; broad physical-interface/L2 appliance ambitions are intentionally not prerequisites for this roadmap.

### Decisions and open questions for the orchestrator

- **Recommended decision:** explicitly support a validated native DPI-event IDS subset; store unexecutable external formats as non-executable artifacts. If full Suricata/Snort/YARA/Sigma compatibility is desired, choose an actual engine/backend and budget its execution and update model rather than silently emulating it.

- **Sizing/ownership choice:** a future real external engine or host-log Sigma backend is a separate architecture project, not a small importer fix. Preserve overall SRA priority; only schema/visibility repairs needed by its labs are immediate dependencies here.
